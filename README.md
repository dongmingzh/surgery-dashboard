# 胸外科手术运营分析看板

> 面向外科科室管理、月度复盘和数据质控的本地化分析工具。导入 Excel 或 CSV，即可从工作量、术式结构、团队负荷、效率质量和数据完整性五个层面进行分析。

## 它能回答什么

- 本期完成了多少台手术，月均量、微创率和袖式切除量如何？
- 不同医疗组、医生的工作量和术式结构有什么差异？
- 手术量在月份和星期维度如何分布，是否存在排班峰值？
- 患者年龄、性别和疾病结构有哪些特点？
- 如果源数据包含扩展字段，平均手术时长、出血量、术后住院日、急诊占比及结局记录如何？
- 哪些关键字段缺失较多，当前数据是否适合用于管理分析？

## 核心能力

- **Excel / CSV 直接导入**：支持 `.xlsx`、`.xls` 和 `.csv`，自动识别常用中文字段别名。
- **数据只在本地处理**：文件在浏览器内存中解析，不上传到本项目的服务器或数据库。
- **全局联动筛选**：日期、医疗组、医生、手术类别和关键词筛选会同步刷新全部指标、图表和明细。
- **分层管理视图**：包含核心 KPI、管理提示、趋势分析、术式结构、团队负荷、患者构成、可选效率质量指标和数据质量诊断。
- **渐进式指标解锁**：有字段才展示对应指标，避免用缺失数据制造虚假结论。
- **自动归类与人工复核**：可读取已有分类，也可按手术名称识别；人工修正后所有分析即时重算。
- **模板与结果导出**：页面内可下载 Excel 导入模板，并导出当前筛选后的 CSV 明细。
- **响应式设计**：适配桌面、平板和手机，适合会议展示与日常复盘。

## 快速开始

### 在线使用

打开 [GitHub Pages 看板](https://donoghzzz.github.io/surgery-dashboard/)，点击“导入 Excel / CSV”。页面自带 110 条跨 12 个月的完全合成演示数据，可直接体验趋势、结构差异、筛选和图表联动。

### 本地使用

下载仓库后，在项目目录运行：

```bash
python3 -m http.server 8000
```

浏览器访问 `http://localhost:8000`。页面依赖 CDN 加载 Tailwind CSS、ECharts、PapaParse、SheetJS 和 Font Awesome，首次打开需要联网。

## 推荐操作流程

1. 在页面点击“下载 Excel 模板”，或从医院系统导出手术台账。
2. 上传前删除患者姓名、证件号、电话、住院号、病案号和精确地址等直接标识符。
3. 导入 `.xlsx`、`.xls` 或 UTF-8 编码的 `.csv` 文件。
4. 先查看顶部的数据范围、识别条数和数据完整度。
5. 用日期、医疗组、医生和类别筛选目标范围，查看管理提示和各分析模块。
6. 在“医疗组设置”中复核医生分组，在明细表中复核自动分类。
7. 点击“导出当前结果”，留存本次筛选后的脱敏明细。

## 数据字段说明

程序会自动在表格前若干行中寻找表头，因此可兼容部分医院导出文件顶部带标题或说明文字的情况。

### 核心字段

| 标准字段 | 常见别名 | 用途 |
| --- | --- | --- |
| 手术名称 | 手术术式、术式名称、手术操作名称 | 核心统计、关键词搜索和术式分类 |
| 手术日期 | 手术时间、日期、手术开始日期 | 月度趋势、星期分布和日期筛选 |
| 手术医生 | 主刀医生、术者、主刀 | 医生及医疗组分析 |
| 医疗组 | 组别、医疗组别、治疗组 | 医疗组负荷分析；也可在页面补录 |

只提供“手术名称”即可运行基础分析；缺失其他核心字段时，看板会在数据质量模块明确提示。

### 推荐字段

| 字段 | 用途 |
| --- | --- |
| 手术分类 / 分类 / 类别 | 优先采用源数据中的业务分类 |
| 诊断 / 术前诊断 / 主要诊断 | 诊断关键词检索和明细追溯 |
| 年龄 | 年龄段构成 |
| 性别 | 性别构成 |
| 微创标志 | 微创率；缺失时会根据术式中的 VATS、胸腔镜、机器人等关键词推断 |

### 可选效率与质量字段

| 字段 | 解锁指标 | 建议单位或取值 |
| --- | --- | --- |
| 手术时长 | 平均手术时长 | 分钟 |
| 术中出血量 | 平均术中出血 | ml |
| 术后住院日 | 平均术后住院日 | 天 |
| 急诊标志 | 急诊手术占比 | 是/否、1/0 |
| 并发症 | 并发症记录比例 | 有/无、是/否 |
| 出院结局 | 院内死亡记录比例 | 治愈、好转、死亡等 |

> 这些指标仅按导入记录汇总，不等同于经过风险调整的医疗质量评价。跨组比较前应统一纳入范围、字段定义和统计周期。

### 最小示例

```csv
序号,手术日期,医疗组,手术医生,手术名称,手术分类
1,2026-01-08,一组,医生01,VATS右肺上叶袖式切除术+淋巴结清扫术,肺部手术
2,2026-01-09,二组,医生02,胸腹腔镜联合食管根治术,食管手术
```

## 看板模块解读

### 1. 总览与管理提示

六个核心指标用于快速判断规模、团队覆盖、技术结构和数据可用性。管理提示根据当前筛选结果自动指出手术高峰、主要术式、团队负荷和需补全的数据，不替代业务人员判断。

### 2. 趋势与术式结构

月度趋势同时展示手术量和微创率；类别占比、医疗组堆叠图、医生分布和高频术式用于观察结构差异。数量较少时，不建议直接把百分比差异解释为绩效差异。

### 3. 排班与患者构成

星期分布可辅助发现工作日峰值；年龄段与性别分布用于描述病例构成。若源数据没有对应字段，图表会显示无有效数据而非补造数值。

### 4. 效率质量与数据质控

扩展字段存在时才出现效率质量卡片。数据质量模块展示关键字段覆盖率和等级，帮助判断分析边界；建议在正式汇报前优先修复覆盖率较低的核心字段。

### 5. 明细复核

明细表保留术式、诊断、医生、组别及最终分类。人工修正只保存在当前浏览器会话，刷新或重新上传后会重置；长期使用请在源表补充“手术分类”列。

## 分类规则

最终分类按以下优先级确定：

1. 当前页面中的人工修正；
2. Excel / CSV 中的手术分类；
3. 根据手术名称关键词自动识别。

目前包括肺部手术、食管手术、纵隔手术、胸部切除和其他手术。自动分类适合初筛，正式统计前应由熟悉科室口径的人员复核。

## 隐私与安全

仓库内演示数据均由固定规则生成，医生仅使用“医生01”等匿名演示标识，不包含患者姓名或真实医疗标识，不对应任何真实人员。

- 不要把真实医疗数据、导出文件或含敏感信息的截图提交到 GitHub。
- 上传前完成去标识化；即使页面本地处理，也应遵守医院制度和适用法规。
- 公开分享时检查图表标签、悬停提示、明细表和浏览器下载文件。
- 本工具无持久化后端；刷新或关闭页面后，导入数据和人工修正会消失。
- 如发现仓库中存在敏感数据，请按 [SECURITY.md](SECURITY.md) 私下报告。

## GitHub Pages 发布

1. 打开仓库 **Settings → Pages**。
2. Source 选择 **Deploy from a branch**。
3. Branch 选择 `main`，目录选择 `/ (root)`，保存。
4. 等待 GitHub 完成部署，访问 `https://<用户名>.github.io/<仓库名>/`。

本仓库已经启用 Pages；合并到 `main` 后会自动更新在线版本。
